# 支持与验证

本页区分“存在构建目标”和“完成游戏验收”。以下为带日期的本地验证记录，
不代表任意发布包或后续提交都已通过相同验收。

## 运行时范围

- 本分支只接受 `BML_RUNTIME=sdl`，使用 Ballanced SDL CK2/VxMath。
- 已实现动态宿主；配置 `BML_HOST_LINKAGE=static` 会失败。更新器识别静态包元数据，
  不等于已经实现静态 Loader 集成。
- 原生 Mod 使用 `bml.mod` major 1 和 schema 2 ABI 伴随文件；旧 SDL C++ 入口产物需
  迁移重编译。原版 Windows 后端由独立分支维护。
- 默认启用脚本，也验证无脚本构建。
- 本分支不含 IVP v1；不实施 IVP v2。

| 目标 | SDK 目标标识 | 本记录的原生 Player 验收 |
| --- | --- | --- |
| Windows x86、x64、ARM64 | `windows` / `x86`、`x64`、`arm64` | 未运行 |
| Linux x64、ARM64 | `linux` / `x64`、`arm64` | 未运行；X11/Wayland 待验收 |
| macOS x64 | `macos` / `x64` | 未运行 |
| macOS ARM64 | `macos` / `arm64` | 动态版，脚本开启和关闭 |
| 任意静态宿主 | 尚未集成 | 待完成 |

## 已完成的本地检查

2026-11-06，macOS ARM64 Release 动态构建的完整 CTest：脚本开启 **109/109**，关闭 **102/102**。
这是本次快照；可选测试开关和后续新增测试会改变数量。

检查包括安装后和移动 SDK 的独立消费者、C/C++ 原生示例、Native/Interface/IMC/Script
开发工作流、全部仓库内原生 Mod 的构建、32/64 位 ABI 基准（在宿主字长执行）、所选引擎
指纹、Behavior/IMC/配置/命令/输入契约及更新器样例。64 位宿主上的基准检查不表示运行过
32 位程序。

独立 SDK 构建的 Player probe 在脚本开启、关闭时均通过多次独立启动。它检查引擎先于
Mod 的 PostProcess 顺序、输入按下/松开/屏蔽、一次待处理 Render 跳过、命令注销寿命、
配置通知、定时器、脚本值和 CK 对象删除后的借用验证，并检查卸载和干净退出。
原始与部署后的 Mod SHA-256 必须一致；测试部署不修改 Mod 二进制。

可选 `--benchmark-api` 记录常用 API 耗时。包括交替对照的五次本地样本中，目录读取
中位数约 13.5→6.8 µs，键名约 63.6→32.5 ns，屏蔽键盘约 40.8→34.9 ns；原始键盘
控制组仍约 40 ns。这是热路径微基准，不是帧率或其他平台的性能保证。SDK 头文件内的
优化需要重编译 Mod 才会生效。

锚点检查。这些属于编译与启动验证，不代表已执行示例所有玩法分支。

## SDL 后续梳理（2026-11-06）

单独启用 UI 自动化后复现两处 BML+ 构建阻塞：无窗口 Bui 目标缺少 CK2/VxMath
编译依赖，脚本热重载场景仍把组合的 ModRecord 向下转换为 ScriptMod。两处均复用
已有目标和记录中的 Script 字段修复。macOS ARM64 脚本开启/关闭的 UI Loader 构建
及三项 UI 测试均通过；这会编译场景，但没有在真实 Player 中驱动这些 UI 流程。

场景目录和 Session 契约现已加入默认测试，也能不依赖引擎或 Test Engine 独立运行。
CI 配置为在 Windows、Linux、macOS 执行；本地仅运行 macOS。上面的完整套件
数量已包含这两项新增默认测试。

## 更新后的引擎基线（2026-11-08）

本轮使用 Ballanced `a330482`、CK2 `0f414789`、VxMath `91aed4e1`、
RenderEngine `ce0432bc` 和 Player `f3a34f0c`。SdlInputManager 仍为 `f070cf67`。
运行时使用 SDL 3.4.20 和 VxMath 默认的扩展精度模拟。
没有修改 Ballanced 源码或子模块指针。

新版 VxMath 安装包导出 `VxMath::VxMath`。BML 在两处包接入点用别名接受该目标，
保留源码接入和旧包支持。引擎 ABI 检查没有放宽：使用 `BML::Engine` 的 Mod 需按新
头文件和公开编译设置重编译；核心 C 协议不变。macOS SDK 测试改为定位进程实际
加载的 SDL，兼容绝对路径和 `@rpath` 安装名，暂存过程不修改 Mod 二进制。
新移动后的 SDK 和旧版已安装 SDK 均通过消费者测试。

macOS ARM64 开启脚本的源码构建全部 **111** 项测试通过；使用已安装引擎包的
无脚本构建全部 **102** 项通过，两者都包含更新器。每套测试中的三个进程/回环网络
测试起初被沙箱权限阻断，授予所需权限后重跑通过；其他项目在首次运行时通过。
独立的引擎/渲染和输入组件测试 **2/2** 通过。这两种配置未开启无窗口 UI 测试代码。

新版 Player 的临时副本在脚本开启、关闭时各通过 **三次独立启动**。每次均加载
全部十二个仓库内 Mod，并验证 120 次 Process/物理处理、119 次渲染回调、七阶段
输入、Mod 卸载、干净退出及 probe 暂存前后字节一致。这属于启动和运行时回归，
不代表逐 Mod 玩法或画面验收。

安装说明也已改为使用开发安装树中实际存在的 `Mods` 目录；此前文档中的
`BMLMods` 安装组件并不存在。上面列出的其他待验收事项仍然适用。

## 0.4.0 版本同步（2026-11-09）

CMake 的 0.4.0 发布版本已与安装后 SDK 头文件、CMake 包版本及实际 DLL 的字符串、
数字版本接口一致。Windows 资源继续使用同一套生成宏，本轮没有运行 Windows 构建。
原生模板和示例以 SDK 的 `BML_VERSION` 声明最低 Loader 版本；脚本模板、示例、
smoke 夹具及发布命令已同步为 0.4.0。各 Mod 自身版本和历史配置迁移保留各自含义。

原生协议仍为 `bml.mod` major 1，ABI 描述仍为 schema 2，更新清单仍为 schema 2。
发布工具现可处理当前 schema 2 运行时，保留扩展元数据，并拒绝不支持的 C 协议；
schema 1 打包兼容也通过验证。真实 macOS ARM64 的 0.4.0 运行时已生成本地测试签名包，
包内运行时、清单和通道版本均为 0.4.0，测试公钥更新器验证通过。
这不代表发布了正式包或验证了生产签名私钥。

0.4.0 的 macOS ARM64 完整测试：脚本开启 **111/111**，关闭 **102/102**。
Player 已加载全部 21 个更新后的文档、模板脚本示例；两种配置还各通过三轮独立
probe，均加载全部十二个仓库内 Mod。其他平台及完整玩法验收仍按下文列为待完成。
