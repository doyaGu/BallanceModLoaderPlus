# Maintaining the SDL documentation

English and Simplified Chinese guides describe the current `sdl` branch. Update
both when changing user-visible behavior. The public guides are under `en` and
`zh-CN`; `adr` records decisions; historical design drafts and implementation snapshots
are separate context, not the current authoring contract.

## Sources of truth

| Topic | Check against |
| --- | --- |
| Build choices and dependencies | Root `CMakeLists.txt`, `cmake/BMLRuntime.cmake`, `cmake/BMLMod.cmake` |
| Runtime/SDK layout | CMake install rules, component install manifests, `packaging` |
| C ABI and C++ wrappers | `include/BML`, `src/Api`, SDK consumer tests |
| Loader order and cleanup | `src/Loader` and its `ModContext`, real Player probe |
| Script declarations | `src/AngelScript/AngelScriptBindings.cpp`, `ScriptApiSurface.cpp`, `ScriptBuiltinFacade.cpp`, `ScriptBehaviorBindings.inc` |
| ImGui bindings | `tools/asgen`, generated binding report and `docs/api/bml-imgui-api.as` |
| Project commands and packaging | `scripts/bml.py`, template CMake files and workflow tests |
| Updater behavior | `tools/updater`, `scripts/package_sdl_update.py`, signed transaction tests |
| Actual platform coverage | Dated `en/validation.md` / `zh-CN/validation.md` and test artifacts |

Do not turn an old proposal, existing target tag, cross-compile, doctor result or
headless UI catalog check into a claim of completed real-game acceptance.
Original Windows IMod/IBML entry points are removed from this branch, including
private implementations. Dynamic SDL is implemented; static Loader integration
and IVP v2 must not be advertised as available.

## Build the site

Use Python 3.10+ in a virtual environment:

```sh
python -m venv .venv-docs
# Activate it for your shell, or use its Python executable below.
python -m pip install -r requirements-docs.txt
python -m mkdocs build --strict --config-file mkdocs.yml
python -m mkdocs build --strict --config-file mkdocs.zh-CN.yml
```

The English build cleans `site`; build it first, then Chinese into `site/zh-CN`.
The configurations check links and anchors. Both languages copy the three API
assets through `hooks/copy_api_assets.py`. Confirm their contents match `docs/api`
and that `site/updates` does not exist. The docs CI uploads an artifact; it does
not publish Pages or update channels.

Keep site links within each language’s `docs_dir`. Link to the repository URL
for files outside it. Check README/SDK/template links separately because MkDocs
does not build those files.

## Refresh editor declarations

`bml-script-mod-api.as` documents BML’s registered methods/properties/enums; it is
an editor stub, never runtime code. Match changes to the existing registration
site, including property access, retention annotations and callback signatures.
`bml-imgui-api.as` is generated by `python tools/asgen/asgen.py generate --root .`
from the checked-out cimgui metadata; regenerate it with its binding sources
rather than changing it independently. This checkout does not include the
required `deps/cimgui/generator/output/definitions.json` and
`structs_and_enums.json`; full regeneration requires matching cimgui metadata.
The property-reference sections can be regenerated from `object_properties()`
through `emit_stub`, which uses the same metadata as the runtime emitter.
Check declarations against the compiled registration source when refreshing
those sections. The documentation CI runs the standalone emitter regression:

```sh
python -m unittest discover -s tools/asgen/tests
```

The combined `as.predefined` needs a CKAngelScript API export from a matching
host. Build an isolated docs runtime with `-DCKAS_ENABLE_API_EXPORT=ON` while
building the matching CKAngelScript source. Launch its prepared Player with
`CKAS_EXPORT_SCRIPT_API` set to an absolute JSON output path. On POSIX, for example:

```sh
cd "/path/to/disposable-game/Bin"
CKAS_EXPORT_SCRIPT_API="/absolute/path/ckas-api.json" ./Player
```

On Windows set that environment variable in the launching shell and run
`Player.exe`. For a flat game use its root as the working directory. Never enable
exports by patching Player or changing engine source. Keep game assets and all
runtime dependencies matched; this can use a disposable Player copy.

From the BML+ source root, use CKAngelScript’s existing generator:

```sh
python ../CKAngelScript/tools/generate_as_predefined.py \
  --api-json /absolute/path/ckas-api.json \
  --output docs/api/as.predefined \
  --append-file docs/api/bml-script-mod-api.as \
  --append-file docs/api/bml-imgui-api.as
```

The checked-in combined file currently reflects a 2026-11-06 macOS ARM64 SDL
host with AngelScript 2.38.0 and DynCall OFF. Platform-sized aliases and optional
FFI differ by host. Do not regenerate it from an unrelated original-Windows API
catalog and assume pointer sizes or available bindings still match SDL. Record
the reference configuration in both API-reference pages.

## Verify examples

Build `examples/native-mod`, `native-c-mod`, the interface provider and its
independent consumer against an installed/relocated SDK. Install the provider’s
headers/CMake package before configuring the consumer. Compile generated IMC
examples in both languages; C++ record names end in `Value`, script names do not.

For complete script examples in fenced blocks and tutorial assets, stage each
as a separate Mod in a disposable runtime. Give copies unique IDs to avoid
collisions; preserve the source and package each generated include. The
`tests/player/sdl/RunPostProcessTest.py` runner accepts `--mods-from` and repeated
`--expect-mod`, checks loaded state, lifecycle cleanup and unmodified probe
hashes. A startup pass proves compilation/loading, not all level-specific
branches or physical/visual behavior. Label excerpts that need a containing
callback or earlier declarations so authors do not mistake them for full files.
